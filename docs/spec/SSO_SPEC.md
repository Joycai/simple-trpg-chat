# 单会话登录 规格说明

> **术语说明**：本规格描述的是「同一账号同一时间仅允许一个有效会话」，准确术语为
> **单会话登录 / 登录互斥（Single Session）**。
> 注意：这**不是**业界的 **SSO（Single Sign-On，单点登录）**——SSO 指跨多个系统的统一身份认证，
> 与本规格无关。早期草稿中的「单点登录 / SSO」表述为笔误，已更正。

本工程支持单会话登录。

## 单会话登录

单会话登录表示同一个时间，每个账号只能存在一个有效会话。**后登录者优先**：新登录直接成功，旧会话的令牌被失效，**不做任何确认提示**。

**适用范围：**

- 普通用户、**管理员**账号：**均受**单会话约束。
- **Bot 账号：豁免**，不受单会话约束。

## 登录行为（无提示，后登录者优先）

假设 **User1** 使用 **account1** 账号已经登录（持有有效会话令牌）。

当另一 **User2** 使用 **account1** 登录时：

1. **不弹任何「账号已登录」提示**，User2 直接登录成功。
2. 系统为该账号生成新的会话令牌，**User1 原有令牌随即失效**。

> 取舍说明：因取消了登录前的确认步骤，若两人共用同一账号，会出现互相顶号、来回踢出的情况（ping-pong）。
> 这是「最小开销」方案的已知代价，对本工具的使用场景可接受。

## 被顶号用户的失效提示（非实时，下次交互时展示）

被顶下线**不做实时推送**。**User1** 在**下一次交互**（任意页面请求 / 操作）时：

1. 系统校验其会话令牌，发现与服务端不一致 → 判定本会话已失效。
2. 将其重定向回登录页。
3. 在登录页展示提示：账号**已在其他位置登录**，本会话失效，并附最近一次登录的来源 **IP 地址：xxxx**。

**提示来源与区分：**

- 失效原因需区分两类，给出不同文案：
  - **令牌不一致**（被顶号）→「您的账号已在 IP:xxxx 登录，本会话失效」。
  - **账号被封禁** → 走原有的封禁提示，不归本规格。
- 来源 IP 取该账号 `login_history` 中**最近一条**登录记录的 IP（即顶掉 User1 的那次登录的 IP），登录时已自动记录，无需额外采集。

## 限流封禁（暂不实现）

> ⚠️ **本节为暂缓需求，当前版本不实现。**
>
> 原设想：短时间内（如一分钟内 5 次「顶号」行为）对该账号登录封禁 5 分钟。
> 因存在「掌握密码即可锁死账号」的自锁 / 拒绝服务副作用，且口径需进一步明确，
> **暂时忽略此要求**，留待后续单独评估。

## 实现要点（最小开销）

本方案**复用现有的 last-write-wins 令牌轮换机制**，几乎无新增基础设施：

- ✅ **已具备**：登录时轮换 `users.session_token`（`src/auth.ts`）、会话校验令牌一致性（`src/auth.config.ts`）、登录 IP 记录（`src/lib/login-history.ts`）。
- 🔧 **需新增**：会话失效时**不再静默登出**，而是读取最近登录 IP、带「已在别处登录」原因重定向回登录页并展示。
- 🔧 **需调整**：将「令牌不一致」与「账号被封禁」两种失效原因拆分，分别给出文案。
- ❌ **无需**：会话过期列、活跃会话检测、登录前确认弹窗、登出时清理令牌（登出后 cookie/JWT 已失效，DB 残留令牌无害）。
