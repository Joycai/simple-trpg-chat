# AI 素材生成面板：首版设计

状态：首版已实现于 0.27.0。下文保留设计契约，部署与实现说明见文末。

## 1. 范围与产品行为

为自己的房间角色生成立绘并裁剪头像；为已有权限创建/编辑的道具、线索、人物资料生成插图。所有入口共用一个生成面板，支持连续生成、保留候选、比较和选用。

首版不扩展道具编辑权限：普通玩家能生成自己的角色图，但不会因此获得房主素材库的编辑权限。情报（info）当前没有图片展示入口，首版不新增；人物资料（character）与玩家角色卡是不同对象，两者都可接入。

首版是文字生成图片，不承诺跨次角色外貌一致性。不做参考图、局部重绘、自动批量抽卡、聊天发送或公开素材广场。无需配置对话模型，也无需绑定 Bot。

## 2. 入口

### 角色卡

在自己的角色卡头像区域增加带文字的「AI 生成立绘」按钮，与「上传图片」并列。查看别人角色卡时不显示；首版不提供代他人生成头像。

头像旁保留「查看立绘」入口。立绘是独立的完整图片引用，头像是从中裁剪的方形图片，两者不互相覆盖。生成面板使用当前角色卡草稿中的可见字段，未保存的描述也可以参与生成。

### 道具 / 线索 / 人物资料

在现有图片区统一显示「上传图片」「AI 生成」；已有图片时依然显示这两个操作。AI 生成不会提前清空旧图片。选中并应用后只更改表单草稿，原编辑器的保存按钮负责正式提交。

没有可用服务时，生成入口显示禁用原因「暂无可用图片服务」，可进入个人 AI 设置；不引导普通玩家进入管理后台。上传图片仍可使用。

## 3. 桌面 UI 线框

面板建议最大宽度 1040px、高度不超过 90dvh。标题和底栏在滚动容器之外。

```text
┌────────────────────────────────────────────────────────────────────┐
│ ✦ 生成角色立绘                        候选仅自己可见            × │ 固定
│ 用于：若杏 · 当前房间                                               │
├─────────────────────────┬──────────────────────────────────────────┤
│ 图片服务                │ 候选图片 · 3 张                           │
│ [图标 服务名称       ▾] │ ┌─────────┐ ┌─────────┐ ┌─────────┐      │
│ 站点共享 · 每次 X 点     │ │候选 1   │ │候选 2 ✓ │ │候选 3   │      │
│                         │ └─────────┘ └─────────┘ └─────────┘      │
│ 画面用途                │                                          │
│ [半身头像] [全身立绘✓]  │ ┌──────────────────────────────────────┐ │
│                         │ │                                      │ │
│ 根据资料整理描述        │ │          当前选中图片                │ │
│ 已读取：背景、已填属性  │ │          等比完整显示                │ │
│ [重新读取当前资料]      │ │                                      │ │
│                         │ └──────────────────────────────────────┘ │
│ 生成描述                │ 候选 2 · 服务名称 · 生成时间              │
│ ┌─────────────────────┐ │ [放大查看] [查看本张描述] [删除候选]      │
│ │可自由修改的提示词…  │ │                                          │
│ └─────────────────────┘ │                                          │
│ 风格 [跟随描述      ▾] │                                          │
│ ▸ 本次服务规格          │                                          │
├─────────────────────────┴──────────────────────────────────────────┤
│ 每次生成 X 点 · 当前余额 Y       [再生成一张] [使用此图并裁剪头像] │ 固定
└────────────────────────────────────────────────────────────────────┘
```

初次没有候选时右侧为空态「描述你想要的画面，生成后在这里挑选」，按钮为「生成一张」，选用按钮禁用。有候选时「再生成一张」永远使用左侧当前描述；「使用此图」永远使用右侧明确选中的候选。新结果追加，不自动抢走用户当前选择；首次完成时自动选择第一张。

风格选项建议：跟随描述、写实、插画、水彩、像素。风格只是提示词修饰，不伪装成供应商原生参数。画面用途：角色为半身/全身，道具为物品特写/场景陈列，线索为实物证据/文书/场景。文书提示说明「精确文字建议后期添加」，不保证文字还原。

服务选择展示共享/个人身份、每次站点点数及简短规格。个人服务显示「站点不扣点，上游按服务规则计费」，不能标成免费。首版沿用服务配置的尺寸、质量和费率，不开放可能改变成本的尺寸/质量覆盖；用途改变构图提示，不擅自改变服务规格。

## 4. 手机 UI 与滚动

小于 768px 使用单列，同一个面板内以主题分段按钮切换「描述」「候选（N）」，切换保留状态；没有候选时也允许进入候选页查看空态。平板/桌面使用双栏。320px 宽度必须可用。

```text
┌──────────────────────────┐
│ ✦ 生成立绘             × │ 固定标题
│ [描述] [候选（3）✓]      │ 固定分段导航
├──────────────────────────┤
│ [候选1] [候选2✓]         │ 两列缩略图
│ [候选3]                  │
│ ┌──────────────────────┐ │
│ │    当前选中图片      │ │ 内容区域独立滚动
│ └──────────────────────┘ │
│ [放大] [本张描述]        │
├──────────────────────────┤
│ 每次 X 点 · 余额 Y       │ 固定底栏
│ [再生成一张]             │
│ [使用此图并裁剪头像]     │
└──────────────────────────┘
```

面板用 flex column，标题/底栏 shrink-0，正文 min-h-0 overflow-y-auto；桌面两栏各自滚动，手机仅当前页滚动。底栏计入 safe-area-inset-bottom，支持 dvh 和软键盘缩小视口。长名称允许换行；所有操作可触达，不以横向滚动隐藏按钮。完成生成后显示「新候选已生成 · 查看」，不强制切页打断输入。

## 5. 主题控件契约（实现验收硬要求）

“不使用原生控件”指不出现浏览器/操作系统默认的选择菜单、确认框和未主题化外观；文本输入仍使用有语义的 input/textarea，配齐主题样式及 label。

| UI 元素 | 实现要求 |
| --- | --- |
| 主面板 | OverlayShell + portal，保留 overlay-modal、theme-border、rounded-theme；沿用弹层动效 |
| 服务、风格选择 | BadgeDropdown，自绘 trigger 与菜单；禁止 select/option，包括仅包了样式的原生 select |
| 用途、手机页签 | 主题按钮组，正确 aria-pressed 或 tab 语义；可见选中标记 |
| 提示词 | bg-input-bg / border-input-border / text-text，主题焦点环、占位色及禁用态 |
| 生成按钮 | bg-ai / text-ai-foreground；普通主操作用 primary/primary-foreground |
| 候选选择 | button + aria-pressed，主题边框和勾选标记，不能只靠颜色区分 |
| 错误与完成提示 | Notice，danger / warning / success 语义色；状态区 aria-live=polite |
| 删除、覆盖草稿确认 | ConfirmDialog；禁止 window.alert/confirm/prompt |
| 图片上的工具条 | bg-scrim、text-on-scrim；不得硬编码黑白 |
| 上传与裁剪 | 自绘上传按钮触发隐藏 file input；复用并检查 ImageCropper，裁剪缩放控件也需主题化 |

菜单 portal 必须继承当前房间的有效主题及明暗模式，不能意外回退到全站主题。层级保证编辑器 < 生成面板 < 预览/裁剪/确认，菜单位于所属弹层之上；不能只不断增加 z-index。弹层栈需隔离焦点，Esc 只关闭最上层，关闭后回到触发按钮。BadgeDropdown 现状不能视为完整键盘支持的保证，实现时补齐方向键、Home/End、Enter/Space 选择及焦点返回，并验证超矮视口的菜单高度限制。

覆盖 default、parchment、cthulhu、shrine、rainglass、aether 六主题的 light/dark。使用现有颜色、字体、圆角 token，不新造固定紫色的 AI 弹窗。减少动态效果模式下不播放持续装饰动画。

## 6. 描述辅助

首版采用本地模板整理，不额外调用 LLM 或产生文本模型费用。图片模型依据整理后的描述作画。文案使用「根据资料整理」，不声称已由语言模型分析。

- 角色：只取当前可读的名字、职业/身份、外貌、背景和已填写属性；字段依照房间规则 schema 获取标签。缺失值不当作 0，不读取隐藏资料、其他成员或聊天记录。
- 属性：以真实规则标签和值附带为参考，不跨规则硬套数值阈值；注明优先遵循明确外貌、属性仅辅助表现气质。职业/属性不自动决定性别、年龄、肤色等。
- 人物资料：名称、basicInfo、detail；道具：名称、appearance、extra；线索：标题、text。用户可删掉不想发送的细节。
- 没有资料时不虚构人物设定，显示空提示词及简短占位示例；用户手写即可生成。
- 首次打开生成可编辑初稿；之后表单变更不自动覆盖用户提示词。「重新读取」展示新草稿供确认替换。
- 点击生成前可展开「将发送的完整描述」，包含用途/风格修饰。最终文本、服务规格与价格快照绑定每次任务；左侧后续编辑不会改变已提交任务。

## 7. 生成、抽卡与应用

每次点击只请求一张；同一素材会话最多一个在途任务，生成按钮临时禁用，其他编辑和聊天不受阻塞。全用户并发及频率在服务端限制，切标签页不能绕过。重复点击用幂等键防止重复扣点；用户主动再生成使用新的键，不自动重试付费请求。

状态：排队中 → 生成中 → 已完成 / 失败 / 待核对。进度使用文字与加载图标，不显示虚假百分比。超时且上游结果不明显示「结果待核对」，不得静默重新收费；失败显示脱敏错误和明确的点数结算状态。用户可主动发起新请求，但需看到这是新的付费生成。

关闭面板不取消已提交任务，返回编辑器显示「图片生成中 / 有新候选」入口。重新打开或刷新后可以从本人房间内的「最近生成」找回会话；未保存素材用服务端 draftId 区分，不按相同标题合并。首版承诺恢复生成描述、候选及任务，不承诺恢复原编辑器所有未保存字段。

候选建议保留 7 天，每个会话最多 20 张；达到上限要求删除候选后再生成，不悄悄删除旧结果。页面说明到期时间。待核对任务不能被普通清理删除账务证据。

应用行为：

- 道具/线索/人物资料：「使用此图」写回草稿，返回原编辑器；保存失败保留候选与草稿，取消编辑保留原图。
- 自己的角色：「使用此图并裁剪头像」进入方形裁剪，按钮明确为「保存头像与立绘」。这与现有头像即时保存行为一致，不误导用户以为依赖角色属性保存。两项引用原子保存；取消裁剪返回候选，不更新头像。
- 点击缩略图只选择，不能触发保存或扣费。放大不改变选择。删除候选不退款；已被正式素材引用的图片不随候选删除而消失。

## 8. 服务端实现边界

现有图片接口并非直接可用：ImageJob 强依赖 Bot、hostId 和聊天频道，结果写聊天缓存并发送消息。需提取共用请求/计费执行层，明确区分 bot_chat 和 user_asset 两种任务用途，保持已有 Bot 行为。

user_asset 的发起者与扣点主体为当前用户：只允许管理员共享服务或本人个人服务，不能借用房主私有凭据。共享服务按现行规则扣发起者点数，管理员豁免；个人服务不扣站点点数。报价来自服务端，变价后要求重新确认新报价，不接受客户端费率。

新增素材会话、候选及正式素材引用：记录 ownerId、roomId、用途、draftId/目标对象、任务与价格/描述快照、过期时间。生成权限、读取任务、读图片、应用图片分别校验；应用还要复查对象编辑权限及当前房间成员关系。用户不得通过候选 ID 访问他人图片。

素材交付保持私有，不调用 dispatchMessage。客户端可轮询本人任务状态，或采用严格定向事件；不向房间广播提示词和候选。后台任务继续使用持久队列与唯一认领；Bot 与素材都受既有全局并发上限管理。

图片写入独立的持久素材存储，不使用可随聊天缓存删除的地址。候选读取需鉴权；正式道具图片根据素材/分发的现有可见性授权，不能让猜到 URL 的房间成员读取未分发线索。头像与立绘按照角色资料权限读取。正式引用采用服务端 assetId 校验，不能仅相信任意 URL。

候选生成成功即是本次交付和结算节点，不以是否选用判断扣费；用户丢弃候选不退生成费。站点结算失败/未知上游结果延续现有核对原则。对账脚本必须按任务用途查询交付证据，不能继续只查聊天消息后误退款。应用和素材清理通过事务/引用保护避免选用中的图被删除，已正式引用图片不会过期。

## 9. 实现拆分与验收

1. 提取图片任务的用途、授权、扣费与交付接口；补齐私有候选/持久素材、清理与对账。
2. 共用 AiAssetStudio（名称暂定）：主题选择器、描述模板、候选列表、预览、状态恢复；由源编辑器管理携带上下文的弹层状态。
3. 接入 CreateEditModal 与自己的 CharacterPanel / AvatarColorBand；增加完整立绘引用与查看入口。
4. 中英文文案同步，验证权限、收费、异步及主题布局。

验收重点：

- 资料为空、部分填写和未保存时提示词正确；手工修改不会被后台更新覆盖。
- 两次生成保留两张候选；选旧图再生成不会被新图抢选；应用/保存/取消边界正确。
- 关闭、刷新、多个标签页、余额不足、服务撤销、成员退出、保存失败及结果待核对可恢复。
- 用户 A 不能访问 B 的任务、候选或未分发素材；玩家生成不扣房主点数；Bot 原有交付不回归。
- 六主题 × 明暗 × 320/390/768/1440px，中文/英文长文案，软键盘与低高度窗口均检查。
- 标题与操作栏始终可达，菜单不裁切，裁剪取消不覆盖现有头像，键盘完整操作；不出现原生选择菜单/确认框。
- 候选到期清理不影响已应用素材；管理员聊天图片清理不影响头像、立绘或道具配图。

## 10. 首版实现与部署

- `AiAssetStudio` / `AssetStudioEntry` 接入角色卡与道具、线索、人物资料编辑器。角色资料整理为本地模板；没有额外 LLM 调用。
- 创建编辑会话和生成任务时鉴权；一个用户最多一个未结算的素材任务，每分钟最多三次。每个会话最多 20 个可见候选，最近列表最多 30 个会话；相同目标重新打开会恢复最近会话。尚未提交的提示词编辑不跨刷新恢复。
- 报价绑定实际扣点金额，在用户行锁内复核（包括管理员豁免变化）。轮询发现服务移除或报价变化后暂停生成，用户需明确接受新报价或选择服务；不自动切换服务。任务快照记录实际扣点、付款角色和图片规格。
- 请求发送前的 URL/SSRF 校验失败会返还预扣点数；已发送但结果未知的请求继续保留待核对。候选轮询按版本隔离，不覆盖刚提交的结果。
- 首版风格与构图选项不改变服务规格或价格。最近会话恢复提交前的描述，风格/构图控件回到默认值；每张候选可查看实际完整提示词。
- 当前无可用服务时仍允许打开面板查看历史候选；面板显示原因，生成按钮禁用。没有跳转个人设置的快捷按钮。
- `user_asset` 任务复用持久图片队列、协议传输与结算逻辑；候选落库为交付凭证。网络结果不明时保留待核对状态，不自动重试。运行 `pnpm db:reconcile-images` 查看，人工确认后 `--apply` 结算。
- **升级前运行 `pnpm db:push`**：新增 `asset_sessions`、`generated_assets`，以及 `room_members.portrait_url`。本变更只需新增表和字段，不需要删除或截断旧数据。随后重启 Node 服务。
- 图片保存到 `AI_ASSET_DIR`（默认 `cache/ai-assets`），部署时必须持久化此目录，且所有应用实例使用同一存储。图片经鉴权的 `/api/assets/[id]` 读取，不进入聊天图片清理范围。
- 候选 7 天后不可继续选用；运维用 `pnpm db:cleanup-assets` 预览，`pnpm db:cleanup-assets --apply` 清理过期/手动隐藏且未正式引用的图片。建议每日运行。被正式引用的图片长期保留；首版不自动回收曾被正式引用、后来被替换的图片。
- 与既有图片 worker 相同，需要常驻 Node 进程，不能依赖会冻结进程的 serverless 执行环境。
- 验证采用模拟上游与独立数据库 schema，不调用真实付费服务。真实供应商出图质量与耗时仍取决于已配置服务。
