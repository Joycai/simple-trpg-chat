## Phase 0 — Critical (fix before any production traffic)

### Task C-1: Fix host message visibility filter (SEC-01 + BUG-03)

**Findings:** SEC-01, BUG-03  
**Files:** `src/app/actions/room.ts:370-396`, `src/app/actions/room.ts:542-575`, `src/app/rooms/[id]/page.tsx:81`  
**Effort:** 1 h

The same broken visibility predicate appears in three places. The `not(type='system')` arm of the host `or` clause leaks all non-system private messages (including player whispers) to the host.

**Correct logic for the host case:**
```
Show message if:
  NOT isPrivate
  OR (isPrivate AND (targetUserId IS NULL
                  OR targetUserId = currentUserId
                  OR userId = currentUserId))
```

Steps:
1. Locate the shared host-filter helper (or inline predicate) in `room.ts`.
2. Remove the `not(eq(messages.type, 'system'))` arm from the host `or` clause.
3. Replace with: `or(isNull(messages.targetUserId), eq(messages.targetUserId, userId), eq(messages.userId, userId))` — guarded by `isPrivate`.
4. Apply the identical change in `loadMoreMessagesAction` (lines 542-575) and `rooms/[id]/page.tsx` (line 81).
5. Write a unit test: host sends message, player A whispers to player B, host must NOT receive the whisper.

### Task C-3: Execute AI tool calls sequentially within a turn (BUG-01)

**Findings:** BUG-01  
**Files:** `src/lib/ai_agent.ts:508-760`  
**Effort:** 2 h

The `Promise.all(toolCallPromises)` pattern causes concurrent DB mutations when the LLM returns multiple tool calls in one response.

Steps:
1. Replace the `Promise.all` dispatch with a sequential `for...of` loop over `toolCallPromises` (or an ordered promise chain).
2. For read-only tool calls (`inspect_item`, `get_character_card`), concurrent execution is safe — identify and separate them.
3. For write tool calls (`send_message`, `set_character_card`, `roll_dice` with state writes), enforce sequential execution.
4. Verify the change does not break single-tool-call turns (the common case).
